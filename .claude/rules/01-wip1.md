# Rule: WIP=1 — One Feature at a Time

## Principle

> **Only one feature active at a time. Complete it (verification PASS) before starting the next.**

Agents tend to "do just a little more," leading to scope creep and under-completion. Context capacity C ÷ k concurrent tasks = C/k per task. When C/k drops below threshold, no task completes.

## Enforcement

### When assigning a feature

```
=== TASK ===
Feature: {FEATURE_ID} - {TITLE}
Description: {DESCRIPTION}

=== CONSTRAINTS ===
1. This is the ONLY feature — do nothing else
2. Complete → run verification → report result
3. Verification: {VERIFICATION_COMMAND}
4. No refactoring, no fixing bugs outside scope
5. If you hit an unmet dependency, report BLOCKED

Begin.
```

### When the agent offers to "do a little more"

Agent says: "I could also add validation while I'm here..."
Response: **No. Only work on the current feature. Log that idea in DECISIONS.md or as a TODO for a future session.**

### When the agent has already overreached

> "You've modified code outside the scope of {FEATURE_ID}. Use `git checkout -- <file>` to revert unrelated changes. Then continue with {FEATURE_ID} only."

## Overreach Warning Signs

- ❌ Agent asks "should I also do X?"
- ❌ Agent starts committing unrelated files
- ❌ Agent says "while I'm at it..."
- ❌ Diff shows >5 files for a small feature
- ❌ Execution time exceeds estimate by 2x with no verification result yet

## Empirical

Agents using WIP=1 show **37% higher completion rate** vs. unconstrained. Lines of code negatively correlates with completion rate.
